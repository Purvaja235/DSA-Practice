Check palindrome number

1.A =>  Brute Force (String method)
		
		 int n = 121;

        String s = String.valueOf(n);
        String rev = "";

        for(int i = s.length() - 1; i >= 0; i--){
            rev += s.charAt(i);
        }

        if(s.equals(rev)){
            System.out.println("Palindrome");
        } else {
            System.out.println("Not Palindrome");
        }
		
		Time Complexity => O(n²) ❌ (because += creates new string each time)
        Space Complexity => O(n)
		
		
2.A =>  Better (StringBuilder)
		int n = 1221;
		String s = String.valueOf(n);
		String rev = new StringBuilder(s).reverse().toString();
		
		int result = Integer.parseInt(rev);
		
		if(n == result){
		    System.out.println("This is Palindrome Number");
		}
		else {
		    System.out.println("Not");
		}
		
		Time Complexity => O(log n)
        Space Complexity => O(log n)

3.A =>  Optimal (Math Approach) ⭐ (FAANG preferred)
       	int n = 123521;
		int temp = n;
	    int rev = 0;
	    
	    while(n > 0) {
	        rev = rev * 10 + n % 10;
	        n = n / 10;
	    }
	    System.out.println(rev);
	    if(rev == temp){
	        System.out.println("Palindrome");
	    }
	    else {
	        System.out.println("Not");
	    }
        Time Complexity => O(log n)
        Space Complexity => O(1)

Q2: Why compare with temp variable?

Because n becomes 0 after loop.

So we store original value.

Q3: Why optimal solution is better than String?

Because:

No copying
Works in O(1) space
🧠 FINAL INTERVIEW ANSWER

A palindrome number is a number that reads the same forward and backward. The optimal approach is to reverse the number using %10 and /10 and compare with original number. It takes O(log n) time and O(1) space.
